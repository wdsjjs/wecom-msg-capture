# 消息运营演示台

`demo/` 是独立的 React + TypeScript + Vite 应用，展示消息运营工作流。所有联系人名称、设备、消息及图片均为虚构示例，图片由 `scripts/generate-fixture.mjs` 渲染生成，不来自真实桌面。

## 运行

需要 Node.js 22.12 或以上版本：

```bash
cd demo
npm ci
npm run dev -- --port 4178
```

默认只绑定本机回环地址。初次打开不需要配置任何凭据。

## 演示流程

1. 在左侧搜索联系人或消息，切换未读、人工筛选。打开会话后清除其未读状态。
2. 点击图片查看详情。点击“演示草稿”填入预设文本，编辑后发送；草稿按会话分别保留。
3. 使用输入区的“模拟收到新消息”图标产生虚构入站；全局 AI 和当前会话托管均开启时，返回预设回复。切换人工接待后不再自动回复。
4. 打开设备管理，模拟离线；输入和发送禁用，重新连接不会重放旧消息。
5. 开始历史补录，向前三个会话加入历史示例。发送暂停，历史内容不增加未读、不改变接待设置或最新 live 摘要。恢复期间新观察也标记为历史。
6. 明确结束恢复，再模拟一条新消息，可以重新触发演示 AI 回复。重复补录不会重复插入同一批示例。
7. 在“运行记录”中查看消息、设备、恢复与接待设置变化，按类型筛选。重置演示可恢复初始状态。

所有状态只保存在当前页面内存中，刷新后清空。没有真实 AI 调用、消息接口、设备控制、附件上传、浏览器存储或服务端数据库。消息发送成功仅代表本地模拟成功。

## 验证

```bash
npm test
npm run build
```

浏览器交互回归需要先启动本地服务，并安装 Google Chrome：

```bash
npm run test:e2e
```

`DEMO_URL` 可覆盖默认地址；`PLAYWRIGHT_CHANNEL` 可覆盖浏览器通道。脚本检查搜索、未读、图片、回复、离线、人工接待、补录、恢复后 live 入站、运行记录、重置和多尺寸溢出，并拒绝外部网络请求。验证截图写入被 Git 忽略的 `output/playwright/`。

## 静态发布

`npm run build` 的 `demo/dist/` 可部署到任意静态托管服务。使用相对资源路径，支持子目录部署；不需要后台服务。不要直接双击构建产物中的 HTML，应通过 HTTP 服务访问。

仓库的 `演示工作台发布` GitHub Actions 工作流在 `main` 的演示相关文件更新后构建并部署到 GitHub Pages，也支持手动运行。仓库 Settings → Pages 的来源应设为 GitHub Actions。

## 设计边界

采用会话列表、消息时间线、底部回复区、接待开关和设备状态的运营工具布局。桌面宽屏显示会话信息，较窄窗口隐藏信息栏，手机端在列表和会话间切换。使用中性名称和虚构话术，不分发参考截图。
